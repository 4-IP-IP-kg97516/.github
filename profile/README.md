<p>本文换一个角度，讲四个IP拿到手后怎么按用途分工、怎么在设备上落地、怎么避免地址互相抢占，重点在分配方案而不是命令，最后用问答补细节。</p>
<h2>一、先把四个地址当成四份资源</h2>
<p>四个地址最怕的用法是随手分配，谁先配谁占用。用一段时间以后没人说得清哪个地址在跑什么，出问题只能全部重来。</p>
<p>正确做法是先定分配表，再动手配置。分配表写清编号、用途、责任人和变更记录，四个人以内的小团队也值得写。</p>
<p>地址是稀缺资源，但比地址更稀缺的是排查时间。分配表的价值在于出问题时能立刻缩小范围，而不是省纸。</p>
<h2>二、按业务切分而不是按设备切分</h2>
<p>按设备切分看起来直观，一台机器一个地址，但设备一换分配就乱。按业务切分更稳，业务迁移时地址跟着业务走。</p>
<p>常见切法是管理、生产、测试三条线，第四条留空做应急。三条线各有各的地址，互不借用在排查时非常关键。</p>
<h3>管理线为什么单独给</h3>
<p>管理入口暴露在业务地址上，一旦业务地址被大量访问，管理页面也会跟着卡。单独一个地址，运维通道更稳。</p>
<p>管理地址还应限制来源，只允许固定出口访问。这一步在路由器或者主机防火墙上做，几分钟的事。</p>

<h2>三、地址落地的两种方式</h2>
<p>第一种是地址直接配在设备上，设备自己就是出口。第二种是地址配在网关，下游主机通过网关出去。前者简单，后者灵活。</p>
<p>小规模用第一种就够，一台设备四个地址，配置清楚不容易乱。规模上来以后再用第二种，把地址集中在网关上统一管理。</p>
<h3>网关模式要注意什么</h3>
<p>网关模式下所有流量都经过一台设备，这台设备的性能就是上限。地址多、并发高时要看转发能力，不能只看网口数量。</p>
<p>网关还要做会话保持，同一台内网主机的连接尽量走同一个出口地址。会话乱跳会导致登录状态异常。</p>
<h2>四、避免地址互相抢占</h2>
<p>地址冲突在多地址环境里很常见，症状是某台设备时通时断。原因通常是同一个地址被配到了两台设备上。</p>
<p>避免的办法是配置前先扫描网段，看哪些地址已被占用。配置后再扫一次，确认新地址没有和别人撞。</p>
<p>还有一种是地址被上游设备占用，比如光猫自己也配了同一段的地址。这种情况要登录光猫检查，别只查内网。</p>

<h2>五、四个地址的典型用法</h2>
<p>一个地址做对外服务，一个做内部管理，一个做数据同步，一个做备用。这套分工覆盖了大多数小规模场景，改动也少。</p>
<p>如果业务需要频繁更换出口，可以把备用地址做成可切换的出口，主地址异常时手动切过去，比自动切换更可控。</p>
<h3>切换时要注意什么</h3>
<p>切换前先断开旧连接，再改策略，最后验证。顺序反了会出现新旧出口同时有流量的情况，业务侧看到的就是地址跳变。</p>
<h2>六、长期维护的几条习惯</h2>
<p>第一，地址变更必须记录时间和原因。第二，配置文件纳入版本管理。第三，每季度复核一次分配表是否还准确。</p>
<p>这些习惯不复杂，但能避免大部分低级故障。多地址环境的问题往往不是技术难，而是没人记得当初怎么配的。</p>
<h2>常见问答</h2>
<h3>四个地址可以都配在同一台服务器上吗？</h3>
<p>答：可以，用地址别名的方式追加，但要注意网卡和上游交换机的地址容量，避免超出转发能力。</p>
<h3>地址冲突会导致整个网段不可用吗？</h3>
<p>答：通常只影响冲突的那几个地址，严重时会造成交换机地址表震荡，表现为整段时通时断。</p>
<h3>分配表需要多细？</h3>
<p>答：写到地址编号、用途、责任人和最近变更时间四项即可，过细维护不起来反而没人填。</p>
<h3>备用地址长期不用会失效吗？</h3>
<p>答：静态地址一般不会失效，但长期无流量可能被上游回收，建议定期做一次连通性检查。</p>
